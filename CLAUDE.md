# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A persistent Iroh peer node that validates incoming blobs as OpenTDF files, stores them in Amazon S3 and serves them back from S3. Blobs are keyed by BLAKE3 content hash. Read access to content is controlled by the TDF encryption layer. The node controls who may *publish*: an entitlement plus a publish session for pushes, operator suspensions and content blocks. The first account to push a recording owns it (`moderation/publishers/<hash>`, write-once): nobody else can push it or list it. See `docs/publishing-and-moderation.md` and `src/moderation.rs`.

A publish that drops a recording from the creator's catalog (Hide, a replaced payload, an empty catalog) is its owner's deletion request: each publish records a transition, and the operator's weekly `sweep-deletions` deletes the dropped recordings and superseded envelopes, every S3 version, once 7 days have passed (within 30 days of the drop while the sweep runs weekly). `request-deletion` covers blocked content and creators who can't publish. See `src/deletion/` and `docs/publishing-and-moderation.md` (Deletion requests).

Creators publish a catalog of their recordings as an `arkavo.creator-catalog/2` document, encrypted as the payload of a ZTDF envelope under the creator's campaign attribute; each entry names a recording and carries its metadata TDF (title and attributes under the recording's policy) inline (#39). The node stores the envelope by hash, behind the creator's passkey-signed pointer (catalog v2; pointer `/2` signs the clear index through `indexHash`), never decrypts it, and checks the recordings through that clear index, which the publisher sends alongside; Creator checks the metadata TDFs. `docs/creator-catalogs.md` is the contract between this node, the Creator app and the iOS viewer: routes, status codes, error strings and validation rules there are authoritative.

## Architecture

**Single crate** (not a workspace). Library modules in `src/`, integration tests in `tests/`.

### Data Flow

```
Push:
Iroh peer (QUIC) → Endpoint → BlobsHandler → iroh-blobs provider → FsStore
  (staging only; single-blob pushes only; publish gate on push; pending until
  ingest is done with it; a push whose declared size exceeds max_blob_bytes
  has its connection closed, and so does one that stalls)
  → export to <data_dir>/ingest scratch file → size check
  → validation from the file in spawn_blocking (structure → attributes → assertion)
  → BAO outboard from the file (iroh block size, root checked against the hash)
  → S3 outboards/<hash> → S3 existence check → S3 blobs/<hash> streamed from
  the file (upload retried twice, after 1 s and 5 s) → S3 manifests/<hash>
  (refused or failed → no blob in S3, so `GET /blobs/<hash>` stays 404; the publisher pushes again)
  The store's GC (every gc_interval_secs) deletes every stored blob no pending
  push needs, so the staged copy goes once ingest is done.
Fetch (get/get_many, single blobs only, at most 64 hashes per get_many):
BlobsHandler → S3Server: blocked? → HEAD blobs/<hash> and outboards/<hash>
  (remembered) → the blob's size, then the BAO encoding of the requested ranges
  read through range GETs from both objects. The node keeps no copy.
  Observe and hash-sequence requests are refused.
  A blob without an outboard (ingested before outboards) is refused as "try
  again" while the node computes the outboard by streaming it from S3 once.
  Refusals: Permission (ERR 1) is final (blocked, or not in S3);
  ERR_LIMIT (ERR 2) is "try again" (S3 silent, outboard being computed, 256
  fetches at once, or a transfer S3 broke off)
```

### Key Modules

- **`node.rs`** — `TdfIrohNode`: Iroh endpoint lifecycle, binds QUIC port, loads the FsStore with staging's GC config, runs the node's own blobs protocol handler (`BlobsHandler`) and the ingest loop. The handler keeps open connections by `stable_id`, so an oversize or stalled push's connection can be closed. A push goes to iroh-blobs' provider into the store and raises events: the loop refuses a hash-sequence push, and with a gate also a push without a publish session or of another account's recording (the gate's owner check); `connected` is intercepted only with a gate, to learn the pusher's endpoint ID. A get or get_many never reaches the store: the handler answers it from `S3Server`, after the blocked-hash check (get_many over 64 hashes, hash-sequence gets and observe are refused; at most 256 fetches at once, else `ERR_LIMIT`). Each request type follows its own `EventMask` field (iroh-blobs#270), and push is `Disabled` by default. `wait_and_ingest` waits for the push to end (watching it for size and `push_stall_secs`); `ingest_stored` validates, then uploads with two retries; once a gated push is ingested, `record_owner` creates its owner record (write-once: `If-None-Match: *`, an existing record is kept, a failed create only logged). A push whose connection stalls (`push_stall_secs`) or declares more than max_blob_bytes is closed; a stalled one is then checked like an aborted transfer. S3 client and config shared via `Arc`.
- **`s3_serve.rs`** — `S3Server`: serves a get from `blobs/<hash>` and `outboards/<hash>`, or else a catalog v2 document from `catalog-documents/<hash>` and `catalog-outboards/<hash>` (`Object` says which; a document's owner is remembered so the handler can apply `hideCatalog`). `check()` HEADs both (10 s timeout) and remembers the size of each servable blob (bounded); `send()` writes the size, then the BAO encoding of the requested ranges (`encode_ranges_validated`) through one sequential range GET per object (a GET that sends nothing for 30 s fails). `Refusal::Gone` (final) is a missing blob; `Refusal::Busy` (try again) is an S3 error or timeout, or an outboard being computed. A blob with no outboard, or one of the wrong size, gets its outboard computed from S3 in the background (at most 2 at once, root checked against the hash) and stored. A send that breaks off forgets the blob, so the next fetch asks S3 again (a blob deleted from S3 is then `Gone`). A hash mismatch (the object no longer matches its key), found while sending or computing an outboard, is never sent, logged as an error, and makes the hash `Gone` until restart. A failed outboard computation is not retried for 10 min. A write to a fetcher that makes no progress for 60 s (`PEER_STALL`) fails the send, so a peer that stops reading cannot hold a serve slot.
- **`ingest.rs`** — `validate_from_store()` (export to a scratch file, validate it off the runtime, compute the outboard from the same file) then `upload()` (outboard first, then the blob streamed to S3, then its manifest); `IngestError::Refused` vs `Failed`. A blob of 16 KiB or less has a zero-length outboard. The BLAKE3 hash is the push's; it is not recomputed, but the outboard's root is checked against it.
- **`staging.rs`** — the local store as push staging. A push is pending (`Staging::track`, a `PendingPush` guard) from acceptance until ingest is done with it. The store's garbage collector (the only deletion iroh-blobs exposes), run every `[iroh] gc_interval_secs`, keeps exactly the pending pushes (read before and after listing the store) and deletes every other stored blob. Nothing local is served, so nothing is withheld or persisted. iroh-blobs ends the collector's loop for good after a failed run (iroh-blobs#291), so `Staging::collector_stopped` watches the protect callback (called once per run, after the mark phase and before the sweep, since 0.104.1: iroh-blobs#240): after 5 intervals + 60 s without one, and once no push is pending, `main` shuts the node down and exits non-zero, and systemd restarts it with a fresh collector. The store inlines data and outboards up to 16 KiB (the default); before 0.104.1 iroh-blobs left an inlined outboard's `.obao4` file behind (iroh-blobs#292), and `test_staged_pushes_are_deleted_once_ingested_or_refused` catches that leak. An aborted push can also leave its `<hash>.bitfield` (a few bytes, never read) when the collector deletes it before its entry unloads: iroh-blobs writes a partial entry's bitfield on unload, and `delete` doesn't reach a loaded entry (iroh-blobs#350). The tests' `wait_for_empty_staging` allows that file.
- **`validation/`** — `max_blob_bytes` check, then three stages: `structure.rs` (ZIP central directory + manifest via the `zip` crate from any `Read + Seek`: at most 65,535 members, checked on every ZIP64 end record before the reader reserves, and at most 16 MiB read while opening; manifest bounded to 4 MiB; payload member read to its end so its CRC is checked, and refused if it would inflate past the archive; spec layout `manifest.json` + the member `payload.url` names, or legacy `0.manifest.json` + `0.payload`), `attributes.rs` (required FQN lookup in policy), `assertion.rs` (policy binding hash + optional signature verification).
- **`creator_catalog.rs`** — pure parser/validator for a catalog's clear index (`PUT /v2/catalogs` `index`): at most 1000 entries of exactly `{contentID, version, payloadHash, payloadSize}`, strict (unknown and duplicate keys rejected), unique `contentID`s. `MAX_CATALOG_BYTES` (4 MiB) bounds the envelope and the pointer's `catalogSize`.
- **`catalog_metadata.rs`** — pure manifest checks: the catalog envelope (`check_envelope`: type `application/vnd.arkavo.creator-catalog+json`, `uuid` + `body` only, exactly one campaign attribute of digits or the subject's creator attribute) and whether a recording's stored manifest names an attribute (`has_attribute`, through `extract_attribute_fqns`, which reads policies in the spec form (`{"attribute": "<FQN>"}`) and opentdf-rs's structured form). Metadata TDFs are inside the envelope and checked by Creator.
- **`catalogs_api.rs`** — `GET /catalog-documents/{hash}` (the envelope, `application/zip`), `GET /blobs/{hash}`, `GET /publish/recordings/{hash}` (the publisher's pre-check: `owner` `you` | `another account` | `none`, never naming the other account; `authorize_publisher` first), and `check_payloads`: the per-entry publish checks on an index (blocked → not ingested → size → owner → manifest → attribute; the owner check gives 403 `recording belongs to another account`, else 422 `recording has no owner: push it again`, both with sorted `contentIDs`, 502 for an unreadable record; skipped ungated), ending with the invariant that every recording names the envelope's attribute.
- **`catalog_v2.rs`** / **`catalogs_v2_api.rs`** — catalog v2 (tdf-iroh-s3#27): the creator's passkey-signed pointer (`/2`: seven keys, `indexHash` = SHA-256 of the canonical index, `creator_catalog::index_hash`; `/1` still parses, for `GET` and as a base), the IdP's COSE_Sign1 credential attestation (authnz-rs#104) and the WebAuthn assertion check (pure, in `catalog_v2.rs`); `PUT /v2/catalogs/{sub}`, the only catalog publish (`{document, bundle, index}`: verify the bundle, pointer `/2` only (422 for `/1`), the envelope (`check_envelope`), the index (its canonical hash must be the pointer's `indexHash`, 422) and its entries (`check_payloads`), IdP credential status, exactly one of `If-Match: "<seq>"` or `If-None-Match: *` (428 for anything else, or neither) and its base check (412, tdf-iroh-s3#29; a base index record that won't parse or fails its `/2` `indexHash` is 502; a pointer `GET` hides, by `pointer_hidden`, reads as none), `seq` greater than stored, a campaign envelope only from that campaign's creator (`arkavo_patreon` role `creator` + `campaign_id`, else 403), then the transition's owner reads (an unreadable owner record of a dropped hash is 502, nothing written), then five writes: `catalog-indexes/<hash>` (never served; write-once, `If-None-Match: *`: another index for the same envelope is a 409 and nothing else is written, the same index a retry), the transition (`catalog-transitions/<sub>/<seq>-<digest>`, after the 412/409 so a retry can't rewrite a committed one: `base`, `dropped` from the served base less blocked and not-owned hashes, `added`; `write_transition` creates it only if absent (`If-None-Match: *`); one there (the same pointer sent before) is replaced, `If-Match` its ETag and with a fresh `at`, only while the stored pointer is still the `expected` this publish's pointer write is conditioned on, else kept with a 502; a failed write, an unreadable one, a moved pointer or a lost replace is 502), envelope, outboard, then a conditional pointer write; a stored pointer with no index record, from before envelopes, reads as none) and `GET /v2/catalogs/{sub}` (a token, then the `[catalog.authz]` decision on the envelope's attribute: 403 `not entitled to catalog`, 502 `decision unavailable`; an operator's service CWT, as the moderation API admits one, skips it; `ETag: "<seq>"`). The envelope itself is served over iroh by `S3Server`. The clear campaign listing `GET /catalog/{group}` and its `catalog-index/` were removed: a campaign's recordings are its creator's catalog, and the viewer takes a campaign's creator from its token (authnz-rs#128); the node keeps no campaign → creator record.
- **`tags_api.rs`** — the catalog APIs' shared `ApiState` and `TagStore` trait, `/healthz`, `authorize_publisher` (gated: `PublishPolicy::publisher`; ungated: token verification only) and `authorize_catalog_reader` (a verified token, checked first on `GET /v2/catalogs/*`). The tag routes were retired with catalog `/1`.
- **`node_api.rs`** — `GET /node`: endpoint ID and relay from the running endpoint, `directAddresses` from `[iroh] public_addresses`.
- **`moderation.rs`** — publishing gate, publish sessions (`POST /publish/sessions`, signed by the endpoint key; held in memory and stored at `moderation/sessions/<endpoint>`, which a push on another instance or after a restart reads back, #32; a stored record counts only with the node's keyed BLAKE3 tag, its key derived from the node's secret key and set by `node.rs` once the endpoint binds, #46), suspensions, blocks, catalog blocks by subject (`moderation/catalog-blocks/<sub>`, hiding the tag, v2 pointer and the subject's catalog documents), audit records. `authorize_push`'s owner check runs last (after session, suspension, block, decision): it waits for one of its own `OWNER_LOOKUPS` permits (16, apart from `SESSION_LOOKUPS`), then reads `moderation/publishers/<hash>`, the wait and the read within one 5 s budget, and fails closed (another subject, unreadable, or out of time → refused); skipped without an owner store (`with_owner_store`).
- **`ownership.rs`** — owner records (`moderation/publishers/<hash>`, `{hash, subject, endpointId, at}`, subject canonical): the first account to push a hash owns it, never overwritten. `parse_owner` (strict), `OwnerStore` (the gate's object-safe store), `OwnerView`; the operator commands `claim_owners` (`claim-owners [--write]`: the backfill before the switch, dry run by default, records with `endpointId` `claim-owners`, a hash listed by more than one subject or owned by a non-lister is a conflict, exit 1 on any) and `release_owner` (`release-owner --hash --subject --reason`: deletes every version only if the record names the subject; the reason is printed, not stored).
- **`object_store.rs`** — `ObjectStore`, the bucket as the offline commands see it (keys relative to `[s3] prefix`): `list`, `list_versions`, `get`, `head_owner`, `put`, `create` (`If-None-Match: *`), `delete_all_versions` (`release-owner`, request records), `delete_versions` (only the named version IDs, the current one last; one written since the caller listed stays: the sweep's item deletes); `bodies` (every object under a prefix with its body, in listing order, read 16 at a time: the scan's and the snapshot's reads). `impl ObjectStore for S3Client`; `mem::MemObjects` (tests) is versioned, with `fail_on` injections and `on_before_delete` / `on_before_get` hooks.
- **`catalog_scan.rs`** — `scan`: every pointer, then every index record (the index listing starts only once every pointer is read), read strictly (anything unreadable is `Err`); `ScannedPointer` (subject canonical, `digest` = SHA-256 of the pointer bytes), `Catalogs::live_hashes` (the index record of the catalog a pointer names). A `/2` pointer whose index record is missing or fails its `indexHash` is `Err`. Used by `claim-owners` and the deletion commands.
- **`deletion/`** — deletion requests (`docs/superpowers/specs/2026-11-13-deletion-requests-design.md`, Part 3); pure logic takes `now: i64`, only `main.rs` calls `now_secs()`. `mod.rs`: the record types (`Transition`, `RecordingRequest`, `EnvelopeRequest`, `OperatorRequest` with `Scope` `hash` | `subject`, `SubjectRequest`; `deny_unknown_fields`), their keys, `GRACE` (7 days), `VERIFY_AFTER` (1 h). `snapshot.rs`: `read`, the strict read of every pointer, index record, transition, request, suspension, block, catalog block and owner record (anything unreadable, or not named as its key, is `Err`: nothing is written). `fold.rs`: each pointer's committed transitions (reachable by `base` links; one canonical subject's chains merged in time order) into `recordings/` and `envelopes/` requests (a drop sets pending, the newest wins, so `requestedAt` never moves back; an add cancels, and only an add does); an unreachable one older than `GRACE` behind its subject's pointer `seq` is lost, deleted unfolded, and so is one of any age whose subject has a `deleted` `subjects/` record and no pointer. `due.rs`: `all_lifted` (`--all`'s preconditions, catalog block then suspension, re-checked by every rule that acts on its requests), `view` (`S` pointers of subjects being deleted, `L` listed hashes whatever the visibility, `C` current envelopes), `observe` (untracked envelope objects), `due` (per hash; blocked content is kept except under scope `hash`; a recording needs its owner record to name the requester). `sweep.rs`: `sweep-deletions [--delete]` (dry run by default; writes the fold, deletes subjects (pointers, then every transition under either key) → recordings → envelopes, each item's versions listed before re-reading everything and only those (`delete_versions`), deferring one whose requester's catalog moved; a recording whose pushed objects (blob, manifest, owner record, listed again after the re-read) have a version newer than a pending `recordings/` request's `requestedAt` isn't deleted: every such request moves `requestedAt` forward to the push, restarting its grace (`pushed again`; operator requests, and drops after the push, still delete it); closes a request kept only for `no owner record` whose recording has no object left but outboard versions older than its drop (`due::Decision::unowned`: an earlier run deleted it and failed to write the tombstone, or a push failed after its outboard) by deleting those outboard versions and the request records, no tombstone (`closed recording`); a newer outboard (an upload maybe in progress) keeps it; then verifies tombstones an hour old, listing before its re-read: fresh, relisted, recreated or gone). `operator.rs`: `request-deletion` (`--hash`: each needs an active block and must not be a catalog envelope's, scope `hash`; `--all`: needs the subject's catalog block and suspension, scope `subject` for every live-index and owner-record hash, then `subjects/<sub>`; preconditions before any write; a pending request is left, a tombstone renewed, a pending one of the scope that can't delete the hash rescoped).
- **`publish_decision.rs`** — `[publishing] decisions = local | shadow | pdp` (#35): whether a subject may publish, asked of the platform's decision service (AuthZEN, `publisher` resource, the person + `X-Entity-Token` devices + environment chain). `pdp` fails closed. Asked at session open only: a session the PDP permitted stores the token-free chain, and its pushes are accepted until it expires (#44).
- **`entity_chain.rs`** — the verified entity chain (person, DeviceCheck devices, environment) shared by the catalog and publish decisions.
- **`auth.rs`** — CWT (COSE_Sign1 ES256) verification against the IdP's COSE key set.
- **`store/s3.rs`** — `S3Client` wrapping AWS SDK (`from_config` honors `[s3] endpoint_url` / `force_path_style`). S3 key layout under `{prefix}` (empty in production): `blobs/<hash>`, `outboards/<hash>` (the BAO hash tree, written before the blob), `manifests/<hash>` (read by the publish checks), `catalog-documents/<hash>` (envelopes), `catalog-outboards/<hash>`, `catalog-indexes/<hash>` (never served; write-once: `create_catalog_index`), `catalog-pointers/<sub>` (catalog v2), `catalog-transitions/<sub>/<seq, 20 digits>-<pointer digest>` (one per signed pointer, never served; `<sub>` the pointer key's; conditional: `put_catalog_transition`), `deletion-requests/{recordings/<sub>/<hash>,envelopes/<hash>,operator/<sub>/<hash>,subjects/<sub>}` (written only by the sweep and `request-deletion`; `<sub>` canonical), `moderation/...` (`moderation/publishers/<hash>`, the owner record, is write-once: `create_moderation_record`, `If-None-Match: *`). Every conditional write goes through `send_conditional`: 412, or for `If-Match` a 404 `NoSuchKey` (the object read was deleted since), is lost (`Ok(false)`); 409 (`ConditionalRequestConflict`, a conflicting conditional write still in progress) is sent again after 100 ms, then 500 ms, and a 409 on the third attempt is `Err`, never lost. `S3Client::new_mock` only builds keys; route tests use in-memory stores implementing the store traits (`tags_api::test_support::MemStore`).
- **`config.rs`** — TOML config with sections: `[iroh]` (incl. `gc_interval_secs`, `push_stall_secs`), `[s3]`, `[validation]` (incl. `max_blob_bytes`, `max_concurrent_ingests`), `[validation.assertion]`, `[http]` (incl. `passkey_rp_id`, `passkey_status_url`), `[catalog.authz]` (the decision service for catalog reads and the publish decisions; the other `[catalog]` keys and `[http] catalog_token` are retired and ignored), `[publishing]` (incl. `decisions`). Default iroh port 11204, HTTP 8090.
- **`test_cli/`** — Separate binary for manual testing: `create-tdf`, `push`, `push-raw`, `fetch`, `publish-session`, `publish` (`--secret-key-file` keeps one endpoint key across a session and its push).

## Deployment

Packer AMI build (`packer/ami.pkr.hcl`) for Amazon Linux 2023 arm64; it pulls the gzipped binary from `binary_s3_uri` using `iam_instance_profile`, both required variables (Arkavo's values: `production/ami.pkrvars.hcl`, gitignored). Systemd service runs the binary with `--config /etc/tdf-iroh-s3/config.toml`. Bootstrap script fetches config from EC2 user-data (IMDSv2) if no config file exists. The CloudWatch agent ships the `tdf-iroh-s3` and `tdf-iroh-s3-cert-sync` journal to the log group `tdf-iroh-s3` (stream per instance ID), creating the group with a 90-day retention; the instance role's `logs:` permissions are set up outside the AMI. The switch day (ownership, pointer `/2` and deletion deploy together, with no overlap) and the weekly `sweep-deletions --delete` are in `docs/publishing-and-moderation.md`. Full procedure, TLS and smoke checks: `production/deploy-runbook.md` (Arkavo-specific, gitignored: local only, never commit it; the repo is public).
